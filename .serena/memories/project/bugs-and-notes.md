## v1.4.6 传感器量程选择修复（2026-03-20）⚠️ 重大教训

### Bug 33-37：传感器量程选择连续5次修复失败

#### 问题现象
- 配置面板显示传感器量程100A（正确）
- 汇总清单显示200A（错误）

#### 错误修复历程
| 次数 | 假设的公式 | 结果 |
|------|-----------|------|
| 第1次 | `singleGroupCurrent = maxCurrent / groups` | ❌ |
| 第2次 | 修复描述显示问题 | 没解决根本 |
| 第3次 | 改 calcMonitorConfig 的公式 | ❌ |
| 第4次 | 又改回 singleGroupCurrent | ❌ |
| 第5次 | 用户说"根据分开关电流"才对 | ✓ |

#### 正确公式
```
传感器量程基于【分开关电流】选择：
- 当 groups >= 2: 传感器电流 = maxCurrent / (groups - 1)
- 当 groups = 1: 传感器电流 = maxCurrent
```

#### 根本教训（最重要！）
1. **没有理解业务逻辑就动手改代码** - 凭自己假设公式
2. **不主动询问正确规则** - 不确定时不问，直接猜
3. **用户说"还是错的"时继续猜测** - 应该停下来问清楚
4. **验证走过场** - 只读代码不验证业务逻辑

#### 改进措施
```
❌ 错误做法：凭理解直接改代码
✓ 正确做法：先问"正确规则是什么？公式来源是什么？"

❌ 用户说"还是错的"时继续猜
✓ 停下来问"我可能理解错了，正确规则是什么？"

❌ 说"我验证了"但只读了代码
✓ 让用户确认或提供原始公式/参考文档
```

### 关键变量说明（v1.4.6）
| 变量 | 含义 | 用途 |
|------|------|------|
| `groups` | 单台UPS的电池组数 | 分开关路数、分开关电流计算 |
| `upsNum` | UPS台数 | 开关箱数量 |
| `totalGroups` | 总组数 = groups × upsNum | 监控主机数量、总电池数 |
| `groupCurrent` | 分开关电流 = maxCurrent/(groups-1) | **传感器量程选择依据** ⚠️ |

### 传感器量程选择公式（v1.4.6 确认）
```
传感器量程基于【分开关电流】选择：
- 当 groups >= 2: 传感器电流 = maxCurrent / (groups - 1)
- 当 groups = 1: 传感器电流 = maxCurrent
```
**来源**：用户明确说明"霍尔传感器电流量程是根据分开关电流选的"

### 分开关电流公式
```
分开关电流 = 总电流 / (groups - 1)   // groups=单台UPS电池组数，N≥2时有效
```

## 开发注意事项
1. **函数定义顺序**: 初始化阶段调用的函数必须定义在调用位置之前
2. **file://协议**: 双击HTML使用，IndexedDB可用但有限制
3. **单文件约束**: 所有代码内联，修改时注意不要破坏script标签结构
4. **同步index.html**: 每次修改后必须同步
5. **浏览器测试**: 功能完成后用浏览器验证
6. **语法检查**: 用Node.js `new Function()` 检查JS语法
7. **部署优先**: GitHub Pages（免费无限）> Netlify（有限额）
8. **自我验证清单**: HTML表格列数=渲染函数列数、输入字段=处理变量、Excel数据=代码数据
